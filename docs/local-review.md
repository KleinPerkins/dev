# Automatic originating-account review

The authoring agent coordinates fresh independent review before ready PR creation,
and again after the head, current main/base, merge-base or raw enrollment policy
changes. Prefer a qualified route on the PR-creation account; when no such cloud
route exists use this qualified local capture. Unknown account identity or runtime
blocks delivery. The operator is not the technical reviewer.

`scripts/local_review.py` captures one fresh no-tool Codex turn. It verifies the
actual account before and after, the explicitly enrolled credential store/profile
and CLI version, exact source tuple, clean worktree, raw policy and textual diff.
It retains the one-MiB ordinary input limit. Binary, empty, oversized or incomplete
input refuses; no earlier report can substitute for the current report. The CLI
ignores candidate rules and user configuration, uses frozen reviewer instructions,
and runs in a private disposable directory. All child processes have time/output
bounds and their process groups are terminated and reaped.

The tuple binds immutable repository ID `1459458379`, exactly one observed phase
(`KleinPerkins/dev-temp` or `KleinPerkins/dev`), head/base/merge-base, diff digest,
raw policy digest and opaque originating account. A `dev-temp` receipt is stale
after rename. Predecessor ID `1278387789` never qualifies under either name.

The result is `g1-local-review/v1`, an operationally trusted local capture, not a
provider signature or protection from an owner with equivalent privileges. It
cannot establish the PR's originating account. `scripts/create_review_pr.py`
captures that independently during actual PR creation. Publish the unedited
receipt after fixing findings and recapturing the final tuple.

The registry binds the two enrolled account routes to their qualified CLI,
credential store, capture/creation adapters, reviewer instructions and observed
startup notices. Any change to these bindings requires fresh qualification.
Do not copy canary qualification. The preparation record must include actual
positive and seeded-defect captures from each account and their independent
review. These ordinary captures do not establish full-tree bootstrap review,
actual PR creation, hosted checks or App readiness. Enabled source entries alone
do not activate a writer: publication and the privileged App remain separately
gated by the exact administrative release and live qualification.
