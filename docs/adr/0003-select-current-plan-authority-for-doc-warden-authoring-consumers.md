# ADR 0003: Select current plan authority for Doc-Warden authoring consumers

## Context

The successor repository retains predecessor Doc-Warden plans as historical evidence. Its central authoring and explicit central defect preparation currently refuse without a current approved plan binding. Local typed draft and acceptance routes work independently. The current Doc-Warden v2 delivery plan is governed by the approved PRD, ADR 0002 and the typed acceptance rules. The GSD runtime is limited to authoring and validated draft import.

## Decision

Select PLAN-47f7e608-ce5f-50ae-be86-10d7e95265f9-47a95332-24e2-567d-9cc5-b3df44a60e13 v1 and its paired governance sidecar, once the plan is accepted, as the central plan authority for current Dev authoring and explicit central defect preparation. A single Dev-owned, versioned selector records the current repository key and GitHub repository ID, exact PLAN ID and version, and the accepted-freeze receipt ID as references. Resolve the Markdown and sidecar through the canonical typed artifact location. Validate the sidecar, identity, mode, active approved version and the receipt's exact postimages. Resolve the receipt independently of the selector. Compute approved_plan_digest from the actual validated PLAN bytes. Its old historical or all-zero value is never evidence that a current source is qualified.

Use the same resolver and observed-input set for prepare, validate, apply and explicit defect authority. Bind the selector, both semantic files and freeze evidence, plus the policy, schema, trigger, runtime pin/interface and consumer profile that the operation reads. Refuse missing, changed, ambiguous, superseded, wrong-owner or historical selections. Require an approved explicit selector change to start consuming a successor. Ordinary typed document operations and local defect authoring continue to use the established route independently of central GSD.

This selection allows only the existing bounded authoring/context and draft-import paths. A native PLAN output still requires the pinned native checker. An import never freezes a plan. Fresh runtime qualification, capability installation and adoption use their own destination evidence and approvals. This decision grants no autonomous execution, source-delivery, release, public checkpoint or fleet permissions.

## Verification and reversal

Exercise exact current selection, missing/wrong identity, missing or stale receipt, altered plan/sidecar, superseded plan and parent drift, changes during import and attempted historical replay. Verify both central consumers see the same evidence and preserve frozen bytes. Source delivery uses the normal independent review, CI and Reviewer App. Local activation consumes a verified merged pin and is recoverable against exact preimages. Reverting the selector restores the current unresolved authority behavior and preserves all frozen records and private capability state.
