## Context

Current Dev governs Doc-Warden authoring, canonical plan authority, and private Save-Game continuity. Codex discovered and invoked the installed Doc-Warden and Save-Game skills. The GSD 1.11.0 CLI and Doc-Warden draft import passed on the host, including from a default login shell. The draft import fixture supplied a synthetic checker report. The shipped GSD installer, interface, manifest, and doctor still use Cursor discovery paths. The existing Codex package assembly is inert, with native publication disabled.

The operator has retired Cursor from production use. Codex must support the complete authoring journey, while Doc-Warden's engine, artifacts, policy, CLI, continuity, and transaction semantics remain portable. This decision applies to the bounded GSD authoring integration. It extends the currently accepted governance product toward the broader operator-led development workflow.

## Decision

1. Use the accepted current PLAN and sidecar, normal Doc-Warden preparation and consent, and the existing pinned GSD 1.11.0 authoring contract. A Codex host adapter supplies discovery, authoring entry points, worker invocation, and client evidence. The shared CLI and closed data contracts continue to admit supported client evidence. Client version or discovery paths carry no authority over requirements, artifacts, lifecycle, or approvals.
2. Reuse the owner-approved package assembly and upstream Codex conversion as source inputs. Preserve the exact version, package integrity, dependency lock, package companions, and existing authoring semantics. Admit exactly the four existing authoring skills and only the roles required by their qualified reachability. The prior nine-role authoring allowlist bounds qualification. Resolve the pinned runtime from the declared install record and prove that missing runtime, unsupported role, changed setup, and foreign client/version fallback stop the operation. Retain the present inert bundle contract as historical evidence and use a reviewed successor for activation. Its pinned Node 24.22.2 binary fails during startup on this Mac. The repaired Node 24.22.3 passed authenticated source-text observation. Qualify full bundle and dependency-lock assembly on the working toolchain through the owner route before claiming it is a supported replacement.
3. Begin with project-scoped Codex discovery and role configuration on an isolated approved repository. Validate the exact project trust, paths, client build, supported model/effort route, descriptor bytes, installed runtime, and Skills-owned dispatch policy. The current ordinary-worker route and a native configured GSD role are distinct supported operations. A role launch counts only when the native client proves the actual role selection and terminal outcome. If this build or owner policy cannot support a necessary native role, return the exact missing capability or decision. Preserve partial failure, cleanup, and cancellation as real outcomes.
4. Run the native authoring checker against the exact draft outputs and bind the real report to the existing preview, output digests, checker descriptor, private run identity, and report digest. Validate and import through the normal draft transaction. Require separate established approval to freeze a canonical plan. Keep native reports, transcripts, private state, and credentials out of public source and receipts. Use Save-Game's existing scoped continuity path for explicit pause and resume.
5. Deliver a recoverable Codex-targeted install, doctor, and removal path. Bind target, runtime, paths, exact preimages, toolchain, and native qualification. Reuse the owner transaction mechanism for conflicts, interruptions, replay, and rollback. A production Codex target must work with Cursor absent, including its home configuration and skill paths. Existing Cursor-owned installation records are readable for authorized recovery. Retirement of those files requires its own scoped operation with actual ownership and preimages.
6. Keep implementation, testing, review, merge, and releases with their owning repository capabilities. Supported operator-led development can call those capabilities through their established boundaries. This decision grants authoring only to the GSD adapter. Autonomous phase chaining, agentic security enforcement, unrelated holds, and other capability owner decisions remain separately governed.

7. Before implementation, accept a new typed continuation PLAN and its governance sidecar through ADR 0016 C2a. It binds this decision and current approved authority to retained requirements and named work, tests, and rollback. Continue using the current central authoring selector under ADR 0003. Any later selector change requires a distinct accepted decision.

## Acceptance

- Prove portable headless governance and actual selected Codex discovery in a clean, Cursor-free fixture. Standard GSD tools and document authority must resolve from pinned sources. Verify representative non-native read/write-preview paths produce equivalent decisions and receipts.
- Qualify each of the four production authoring skills in the actual Codex client. Verify supported arguments, reachable role routes, runtime and configuration bindings, allowed writes, terminal results, and refusal of missing or foreign runtime/client/version fallback. Any proposal to expose fewer skills requires an explicit scope decision.
- In an actual qualified Codex session, invoke the supported GSD planning skill, observe a genuine planner and independent checker result as applicable, and import the exact draft after consent. Exercise successful pause and resume and refusal of a stale or conflicting resume in the same scoped journey or an isolated copy. Verify that the private checkpoint remains under Save-Game custody and the frozen current plan and sidecar retain their bytes.
- Verify install and removal in independent homes, recovery after interruption, exact replay, refusal of foreign ownership or later edits, and read-only doctor. Successful activation on the Mac requires the verified merged revision and an exact destination preview and consent. Temporary fixture state is removed after proof.
- Source delivery uses fresh independent review, repository CI, and App merge. Close this unit only after observing the actual merged revision, exact installed pin, and real native Codex authoring evidence. The broader non-technical product delivery and maintenance journeys have separate evidence.
