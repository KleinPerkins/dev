ADR 0004 was accepted through operation aa62595b-2804-4330-9ce5-6c0529dd9a2a. The broader operator outcome and acceptance journeys are recorded in the separate completion brief. This unit qualifies the native authoring path needed by those journeys.

## Acceptance checks

- C1 binds actual current ID/version/digest and freeze evidence for every declared parent. Artifact acceptance is distinct from implementation, release, and host application.
- C2 reports the exact native skill and role discovery observed on the tested Codex build. A parsed role TOML, model offer, unit mock, or CLI shim cannot stand in for native invocation. Missing supported role dispatch stops C4 and has an explicit result.
- C3 tests wrong root, foreign objects, shared destination concurrency, interruption and recovery, replay, later edits, unavailable tools, and legacy receipt readback. Confirm normal shell operation with Cursor unavailable.
- C4 presents real client evidence for authoring and checker outputs, deterministic plan validation, scope-bound import preview, failing mutable or missing authority, Save-Game unavailable/unadopted and stale refusal, privacy, and successful replay. Public evidence contains only closed fields and digests.
- C5 proves required checks on exact published head, authorized App merge, and actual installed merged pin. Production tests use the native application and the default shell. C6 is still required before declaring the complete wider operator workflow delivered.

## Task order and implementation anchors

- **C1 → C2.** Finish typed authority and current repository validation first. C2 starts with the approved source observer, inert package contract and emitter in `_ops/portability/`, the exact `_ops/doc-warden/runtime/gsd-core/` package pin, lock and runtime interface, and the Skills-owned dispatch contract referenced by `_ops/rules/hosts/codex-work-dispatch.md`. Capture exact project discovery, role selection and reachable imports before committing to the production projection. Native capability or owner-policy failure has a written disposition before dependent implementation. Where scoped proof needs a separately authorized native call or owner change, prepare that decision and continue unaffected portable work.
- **C2 → C3.** Extend the owner runtime install/preview, doctor, removal and recovery paths in `_ops/doc-warden/v2/doc_warden/live_install.py`, `runtime_host.py`, the runtime interface, and their existing tests. Keep host selection and discovery in the adapter. Qualify the locked package on the supported normal-shell toolchain under a separate current contract. Retain historical readback. Exercise explicit target, preimages and destination locks, foreign destination refusal, interruption/retry, tampered input refusal and exact rollback. No configuration is published outside declared targets.
- **C3 → C4.** Use the existing `prepare-authoring`, `validate-authoring`, generic consent-bound `apply`, `gsd_plan_check.py`, and `continuity.py` routes as the portable authority. In the isolated project, exercise approved requirements, the four real native skill routes, planner and checker evidence, permitted draft output, exact apply and replay, and genuine Save-Game pause/resume with refusal cases. Compare accepted PLAN/sidecar, Git HEAD/index and private owner records against expected scoped preimages and postimages. Capture sanitized receipts and closed digests.
- **C4 → C5.** Run the policy/docs checks, direct GSD contracts, scoped regressions, `make doc-warden-verify` and `make verify-ci` for the final source. Use the current same-origin review and Reviewer App route in `docs/github-delivery.md`. Verify the exact merged revision. Qualify the real destination, obtain exact host installation consent, apply with the supported recovery preimages, and rerun real native checks against the installed source pin. A failed live verification follows the scoped owner rollback; retain unfinished recovery evidence when ownership or later edits make reversal uncertain.
- **C4 → C6.** Start drafting the next pilot's operator journeys and owner inventory once the disposable native workflow works. Actual pilot qualification follows C5. Measure product delivery, an existing-product maintenance case, and ecosystem or non-product work. Use the owners' existing boundaries. Present the exact external decision only where the evidence requires it.

C1–C5 close native authoring. A successful authoring unit is one prerequisite for the wider C6 product and maintenance outcome.
