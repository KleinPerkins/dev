# Personal Canvas Design qualification proposal

This interface supplies one closed, Codex-only temporary qualification
profile for the unchanged Skills f2301ce payload. Normal owner source acceptance
is a prerequisite to using it on the destination. Source acceptance alone gives
no publication, worker, native evidence or retained installation authority.

The profile reuses the exact currently accepted selected-skill transaction bodies
and helper hashes without modifying their original namespace or two-skill profile.
It binds the complete 85-file Canvas Design tree, two selected font files and both
full OFL notices, current build-23880 app/CLI bytes, preserved native opt-outs,
configuration and other roots, exact absent destination/staging preimages and one
fixed synthetic workload. The broad installer must never be run.

After normal current-base owner checks, independent review and exact source
acceptance, verify an accepted export and prepare a fresh actual destination
preview with `canvas_design_canary.py preview`. Its exact operation digest needs
human acceptance under the transfer's MANUAL-ACTIONS before apply. Revalidate
the actual executing host, supported native worker contract and current offers;
installed app bytes alone do not establish execution-host or model identity.
Any changed profile, source, build, runtime or preimage requires a replacement
preview and applicable fresh consent. No prior canary allowance transfers here.

The intended canary temporarily creates only `~/.codex/skills/canvas-design`
with named staging and starts exactly one separately approved gpt-6.1-sol/high
worker. Native catalog discovery and the actual pinned instruction read must be
observed from its original handle. Wait at most60 seconds first, interrupt if
unfinished, enforce strictly less than120 seconds actual worker duration, and
record terminal status and source/read/artifact observations. No nested workers,
extra roots, downloads, system fonts, services, other clients or Affirm access.
The interface itself never starts a worker.

Perform exact inode-owned rollback after every outcome. Verify removal and all
preserved preimages before independently inspecting saved outputs. Preserve
foreign edits and failed attempts; do not force rollback or repeat a consumed
worker authorization. The one temporary link is never retained by this interface.

The private parent-created fixture has an exact UUID/action marker, original
source notes, four font/license inputs and exactly three final outputs: the
complete philosophy, a single-page static original PDF and bounded worker notes.
The worker may use a private `scratch/` only during authoring; it must be absent
at completion. The preview also binds the compiled existing bundled Python3.12 interpreter and
all741 files in the pypdf, ReportLab, Pillow, pypdfium2 and pypdfium2_raw package
trees, including existing caches and native assets. The worker uses that fixed
backend for authoring/rendering; changed bytes, roots or counts hold apply.
These checks do not qualify the whole OS or arbitrary PDF workloads. Bind actual
invocations and the separately accepted native provider in the operation packet.

Run fixture inspection with the already installed, independently verified PDF
runtime containing pypdf. It checks private modes, exact inventory, stable file
identities, original font/license bytes, philosophy paragraph shape, supplied text,
both embedded font uses and a closed static PDF object graph. Bound process time
and output size at the parent. Parse/shape success is not semantic or visual
acceptance: render the final saved PDF independently, inspect composition,
conceptual fidelity, margins, clipping, font appearance and the refinement pass.
Retain original hashes and native trace/timing/rollback evidence. A separately
reviewed evidence decision and retained owner workflow/preview remain required.

Tests use only private synthetic home/source/configuration fixtures. They do not
admit actual roots, authenticate native tools, prove model execution, accept a
real owner decision or qualify full installation.
