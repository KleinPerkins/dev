## Source boundary and observation transport

Repository IDs are selected before home, manifest, authority or target access.
No arbitrary root, linked-root binding or directory discovery flag exists.
The accepted personal scope and qualified Git/worktree dependencies establish
the actual root, personal origin and identity, HEAD and working-state evidence.
They retain private regular-copied Git metadata and source-storage checks.

Only `.planning/doc-warden.json`, and when the owner view actually requires it,
`.planning/ROADMAP.md`, are copied through the descriptor/no-follow reader into
an owned private disposable snapshot. The exact owner view definitions evaluate
that snapshot. Their one closed HEAD query receives the already-qualified
observation; it starts no owner subprocess. Other process requests refuse.
The returned repository label is explicitly projected onto the fenced source
identity. Schemas and file bytes, metadata, directory memberships and working
state are checked again before the result is returned. A visible late change
invalidates the observation without restoring timestamps or overwriting edits.

Aliases, special/shared/foreign files, unsupported text and resource bounds stay
unavailable. Unrelated artifact bodies and generated-memory bodies are not read.
No source, index, reference, configuration, hook, existing receipt or shared link
is written. Private copies are disposed of after the observation. These fences
detect ordinary drift and visible edits, not a hostile same-user writer.

`--fleet` uses only these selected observations with the owner's logical
deduplication and closed fleet renderer. It never opens the central mixed fleet
catalog or guesses another checkout. Repository numeric IDs remain unknown in
this dependency rather than being inferred from a name or unverified profile.
Unavailable selected checkouts stay explicit and non-mutation-eligible.
The fleet source revision identifies the immutable owner adapter source, not a
live remote or hidden Dev checkout; the owner's default unknown observation
timestamp remains explicit. The fleet-doctor external dependency stays blocked.
Eligibility fields in rendered data supply no mutation or human authority.
