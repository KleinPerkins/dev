# Personal Theme Factory temporary canary

This closed profile qualifies only the required `skills/theme-factory` payload
for the personal migration. It does not broaden INT-008, alter the existing
selected-skill profile, install fonts, or grant retained installation. Source
acceptance, exact temporary-publication and one-worker consent, actual native
evidence, evidence acceptance and retention are separate gates.

## Saved-artifact inspection after a checker correction

The closed HTML subset includes passive `h3` headings and `small` labels. Their
attributes use the same active/external/inline-style refusals as every other
allowed element. A final color declaration may end at its CSS block's closing
brace without a semicolon. All four exact roles, duplicate refusal, palette,
resource, content, private-file and review checks still apply. This is a bounded
shape check, not a general HTML/CSS validator or a rendering/accessibility proof.

A normally accepted checker correction may support read-only inspection of a
saved native attempt. It does not change that attempt's frozen implementation,
preview, action, original result, worker allowance or ownership records:

1. Preserve the original refused result and exact old checker. Verify the original
   accepted source, action/approval, actual native catalog/source-read trace,
   one-worker timing, terminal handle and exact rollback evidence independently.
   Missing or failed native evidence cannot be repaired by a shape-check pass.
2. Verify that the original private fixture still matches its saved file hashes,
   identities and modes, including the operation marker, frozen source notes,
   fonts and complete license. Never edit or regenerate a failed worker artifact.
   The temporary target and staging links must remain absent. Retain unknown or
   changed ownership as a hold; no new publication or recovery is authorized.
3. Export only `fixture.py` and `source-notes.json` from the normally accepted
   corrected revision into a separate private tools directory, verifying both Git
   blobs and SHA-256. Run that checker read-only with the original explicit root,
   operation UUID and action digest, under the existing home/network/write fence.
   Do not replace files in the old accepted export or operation. Preserve real
   HOME/CODEX_HOME, both checker identities/results and all input preimages.
4. Record this as a new corrected-source inspection, alongside the original
   refusal. Verify the unchanged saved artifact's browser, actual-font, contrast,
   semantic and visual evidence separately. The earlier action is not replayed
   and its frozen checker is not relabeled passing. Source and operation-specific
   evidence acceptance remain distinct owner gates; this inspection grants no
   native acceptance or retained installation by itself.

This route starts no model worker, thread, native catalog process, service or
download and creates no native link. A retry requiring another worker or native
publication still needs a fresh exact preview and actual consent. Retention still
requires accepted native evidence, a separately reviewed interface and fresh
retained consent. New canary previews bind the corrected checker normally and
cannot reuse an old action digest.
