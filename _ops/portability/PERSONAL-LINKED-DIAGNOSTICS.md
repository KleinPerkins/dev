# Bound personal linked diagnostics

This component combines the accepted linked backend with the current personal
identity, hook/memory, baseline and v3 profile contracts. It inspects one exact
additional checkout through the existing read-binding route. It makes no network
request, source/configuration change, shared link, worker or service. Source
acceptance and a matching digest do not supply an owner decision, native
publication, additional-root admission or complete migration acceptance.

The owning caller must first satisfy the exact additional-root review and any
applicable human gate. It then supplies the exact binding text and its SHA-256.
The selected repository/common/registry identities, pointer bytes, candidate and
target gitfile backpointer are checked by the accepted linked backend before
checkout bodies. Unknown/stale/extra/duplicate input, aliases, excluded roots and
wrong backpointers remain held. No arbitrary-root or writer parameter is added.

`inspect --binding-sha256 <reviewed-digest>` reads one closed JSON envelope from
stdin:

```json
{
  "schema": "personal-linked-diagnostic-input/v1",
  "binding_text": "<exact binding document text, including its final LF>",
  "responses": null
}
```

For subsequent staged inspection, `responses` may contain the existing closed
`personal-profile-responses/v1` protocol. Responses are untrusted evidence from
the already selected personal connector route; they grant no authentication,
organization visibility, owner approval or writer authority. Repository metadata
identity precedes dependent GET requests. Missing, malformed, partial, timed-out,
forbidden and plan-limited evidence stays unavailable. No alternate auth, fetch,
global/system configuration or old lifecycle state is adopted.

Default hooks are read from the exact bound common Git metadata. Explicit
absolute paths within that same common directory use a separate metadata-only
reader. Explicit relative paths and paths inside the checkout retain actual
checkout semantics: a literal `.git/hooks` override is not remapped through the
linked gitfile to the common hooks. Outside paths, aliases, shared/special files,
generated-memory paths and excluded names remain unavailable. The canonical
marker/current registration-guard/executable checks and missing, inert, foreign
and stale outcomes are retained. Hook bodies are inspected structurally and
never executed.

Memory and tracked AGENTS checks use the linked checkout's own index and root.
Generated-memory file bodies are never opened, emitted or adopted as context;
the accepted backend may copy opaque audited Git objects into disposable private
storage. Tracked memory remains a violation even when status/baseline cannot run.
Tracked AGENTS yields only the existing pointer/learned-heading flags and hashes,
without publishing or adopting its text. Identity keeps local and effective
observations separate. A noncanonical effective personal email is a violation,
including when an unavailable hook causes another component to be unknown.
An original primary manifest pin comparison is not an accepted linked revision.

Baseline uses the complete accepted eligibility and five-file semantics against
the immutable owner templates, using the correct linked HEAD/index/status.
Dirty, detached and non-main checkouts explicitly exclude file compliance rather
than passing unchecked files. Eligible checks retain missing/partial/compliant
aggregation and metadata-only create-only file checks. Profile then applies the
accepted local v3 and staged delivery/review/history contracts under that actual
eligibility. Missing profile evidence is not relabeled compatible legacy state;
current v3 remains incompatible with the old closed-v1 verifier. Full operator
visibility is never inferred.

The canonical doctor's documentation loop explicitly enumerates primary paths
(doctor blob `7e8aed3984be06ad970366313e43e1eebea8d40d`, lines 460/465/473/484/489).
This linked component therefore reports documentation as not applicable for that
route, without executing or claiming a structural check. Required primary
structural documentation, the separate active-v2 documentation capability, and
the full bounded caller/native workflow remain open. This boundary does not
erase or weaken any original required capability.

Each component remains separately visible. A known violation is retained beside
unavailable status/profile evidence. Unproven dynamic response objects refuse the
profile component without erasing independently checked local violations or
emitting the unproven payload. Final baseline/body fences and retained
control readers recheck the combined observation, including ignored profile and
baseline controls, common hooks and generated-memory metadata. A later change
invalidates partial results without cleanup or timestamp restoration. The
accepted own/common private metadata and regular object copies preserve source
bytes, inode and timestamps, with inherited strict copy/process/traversal bounds.
No hostile-same-user-writer protection is asserted.

Exit 1 reports a known violation even if another component is unavailable. Exit
2 reports unavailable evidence without a known violation. Exit 0 reports an
available bounded diagnostic; advisories and drift still remain visible and do
not constitute setup completion. No actual operator linked checkout is opened by
the synthetic test suite or source acceptance alone.

Synthetic fixtures cover common versus explicit hooks, literal gitfile behavior,
own overlays, missing/stale/nonexecutable guards, inactive/external/aliased/shared
and special controls, memory privacy, AGENTS flags, independent identity
violations, all baseline applicability classes, complete eligible baseline/v3
delivery, review drift, plan-limited history and missing staged responses. Late
common-hook, ignored-profile and ignored-baseline edits invalidate joined results.
Plain/split/sparse layouts preserve source bytes/inodes/modes/timestamps, and the
closed CLI input and three exit outcomes are exercised on disposable roots only.
