# Personal primary documentation structural observations

`personal_documentation.py inspect` projects the current doctor's primary-only
legacy `doc-warden.sh check` route over the exact manifest-approved personal
repositories. It has no arbitrary-root, repair, reconstruction, worker, network,
service or native publication option. Use Python `-I -B`; the process refuses
bytecode-writing mode. Source acceptance supplies no additional-root admission,
retained link approval or complete migration acceptance.

Eligibility uses the same current primary worktree and baseline eligibility
contract: only a clean `main` primary is eligible. Dirty, detached and other
branches report `NOT_APPLICABLE` before documentation body reads. This says
nothing about their file conformance. Registered linked worktrees remain outside
the canonical doctor's documentation loop, and this component does not open them.

## Legacy receipts stay separate from state adoption

The legacy owner's receipt namespace is external to each repository. This
projection never scans or imports that old mixed global state directory. Without
explicit staged personal receipt evidence, a file that reaches the receipt
comparison is unavailable, rather than silently treated as receipt-free.

`--receipts-stdin` accepts only this closed observation protocol:

```json
{
  "schema": "personal-doc-receipt-observations/v1",
  "repositories": [
    {
      "repository": "KleinPerkins/skills",
      "namespace": "skills",
      "files": [
        {
          "name": "synthetic.yml",
          "raw_base64": "<base64 of the supplied receipt bytes>",
          "sha256": "<bare SHA-256 of those bytes>"
        }
      ]
    }
  ]
}
```

Repository IDs must be selected exact personal IDs. Namespace must be the
manifest path basename (the `kp-mcp` repository's namespace is `mcp`). Files are
bounded shallow `.yml` names and bytes, never local source paths. A supplied
empty list is an explicit observation of empty supplied evidence, not proof of
source completeness or owner acceptance. The parent workflow must separately
establish source personal/work classification, completeness and permitted
handling. No bytes or checksum in this protocol supplies that authority.

Lookup follows reverse lexical receipt order and the first relevant nonempty
digest, skipping `n/a` and `index_row`. A newer malformed/unqualified receipt
holds the observation rather than being mistaken for absence. Older receipts
after an already found relevant digest cannot override it. No untrusted body is
emitted or used as agent context. The isolated, hash-verified pure PyYAML 6.0.3
SafeLoader has byte/node/depth bounds and no unsafe Python constructors, C
extension, ambient `yaml` import or global Python installation. Its upstream
source/distribution hashes and MIT license are retained under `_vendor/pyyaml_603`.

## Read-only v2 ADR validation inside legacy `check`

The structural branch also invokes the exact current read-only v2 ADR validator
when an ADR has v2 metadata or an in-repository v2 receipts directory exists.
The curated closure preserves decorators and contains only its transitive pure
definitions from the four owner source blobs named in that module. Writer
functions and the original subprocess helper are excluded. Each observation has
an isolated function namespace bound to the nine hash-verified schemas and a
closed private Git reader; shared module globals are not patched.

The disposable validation snapshot carries only fenced documentation, local
configuration, artifact records, freeze receipts and closed event references.
Canonical JSON front matter, schemas, duplicate identities/numbers, relations,
other artifact bodies and external provenance retain their current owner
semantics. Approved ADRs require the existing applied freeze receipt, matching
event and exact postimage bytes. A relocated historical confirmation digest is
not fresh root-bound consent. Plain legacy prose is still checked against v2
freeze evidence before falling back to legacy sections/receipts.

Local asset provenance reads only immutable blobs through the qualified Git
binary and already audited, regular-copied private personal object store.
Commands are closed to top-level identity, commit type, literal tree entry and
blob reads. Real working-path metadata is fenced before source blob access;
unsafe ancestors or leaves cannot be hidden by their absence from the disposable
snapshot. Working asset bodies are never read. The process does not perform
external provider requests. Existing owner provenance observations remain data,
not permission to contact an external system.

Descriptor/no-follow owned-unshared file reads, bounded shallow memberships,
content and metadata fences and before/after primary worktree observations
detect late edits, including ignored documentation/configuration/state. Aliases,
special/shared/foreign files, nested checkout roots, generated memories,
excluded paths, non-UTF-8/binary text and resource bounds remain held. Bounded
observations do not claim protection against a hostile same-user writer. Source
objects, indexes, configuration, links, original journals and primary pins are
never changed, and no timestamps are restored to mask changes.

This is the legacy structural compatibility component only. The separately
required active-v2 documentation capability, full personal Dev caller,
additional-root owner workflow, native acceptance and all original migration
requirements remain independent. Synthetic test evidence is never promoted
into an actual destination approval or capability acceptance.
